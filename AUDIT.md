# Проверка релиза

Проверка выполнена локально в Docker Desktop. Демо использовало загруженное расписание, проверки прав использовали изолированную временную базу и тестовый токен. Telegram Bot API в интеграционном тесте заменён записывающим транспортом.

## Безопасность

- В проде проверены подпись Mini App, возраст подписи, белый список и отказ демо-заголовку.
- Проверены отсутствие ответа на посторонний `/admin`, добавление и привязка ID, отзыв доступа и роли, защита главного админа, пересадка и скрытие. Повторное нажатие той же кнопки сохраняет выбранное состояние.
- Привилегии проверяются на сервере при каждом действии. Telegram ID попадают в ответ веб-админки только для главного админа.
- Проверены CSP, `nosniff`, политика реферера, отсутствие заголовка `Server` за Caddy, лимит тела запроса и запрет кэша для API. Документация OpenAPI отключена.
- Caddy отдельно проверен для локального HTTP и HTTPS с тестовым сертификатом, сжатия gzip и zstd, кэша сборочных файлов и поведения при ошибке 404.
- Проверены Git и Docker-исключения для `.env` и сессии. Локальная сессия переведена в режим `0600`, OCR-контейнер читает её через монтирование только для чтения.
- `npm audit` и `pip-audit` для версий из образов веба, OCR и Telegram-бота завершились без известных уязвимостей в этих реестрах.
- После обновления пакетов и удаления неиспользуемых установщиков Trivy 0.76.1 проверил пять итоговых образов. В PostgreSQL не осталось находок. В вебе, OCR и Telegram-боте остался общий набор находок Debian (50 High, 74 Medium, 79 Low и 14 Unknown). База Trivy не указала исправленных версий пакетов Debian для этих находок.
- В системных пакетах Caddy находок нет. В бинарнике из официального образа Caddy 2.11.9 остались две находки уровня High (`CVE-2026-116587` и `CVE-2026-78661`), семь Medium и одна Unknown. Сканер проверяет версии зависимостей. Применимость каждой находки к работающей конфигурации отдельно не проверялась.

## Производительность

| Сценарий | Результат |
| --- | --- |
| API напрямую, 16 клиентов, 14 секунд до изменений | 229 запросов/с, p95 96,36 мс |
| API напрямую, тот же сценарий после изменений | 397 запросов/с, p95 56,38 мс |
| Через Caddy, 16 клиентов, 42 секунды | 17 637 ответов, 0 ошибок, p95 48,4 мс |
| CPU веб-контейнера | около 1% ядра в простое, медиана 1,50 ядра и максимум 2,09 ядра под нагрузкой |
| RSS веб-процесса | 69,7 МиБ в начале, 70,0 МиБ в конце нагрузки и после неё |
| Кадры в Chromium через Playwright MCP | p95 17,6 мс на десктопе и 17,5 мс на мобильном размере при замедлении CPU в четыре раза |
| Два изображения палубы на мобильном размере | 277 596 байт после оптимизации, 717 624 байта исходных файлов |

Браузерные сценарии покрыли выбор судна, просмотр отсека и выбор дня расписания. Проверены пауза опроса в скрытой вкладке, возобновление опроса при возврате и системная настройка уменьшения движения. Размеры браузерного экрана и замедление CPU эмулированы.

В дополнительном браузерном прогоне после 512 переключений JS-куча после принудительной сборки мусора составила 3186, 3254, 3297 и 3451 КиБ по четырём сериям. В отдельном прогоне после 288 переключений во всех трёх сериях оставалось 450 DOM-узлов. Счётчик обработчиков составил 204, 204 и 221.

Контейнерные замеры охватывают короткую нагрузку. Публичная сеть, реальный Telegram WebView, длительный прогон и квоты внешней доставки сообщений в этот замер не входят. Уведомление отмечается перед доставкой, чтобы переживший перезапуск бот не дублировал его. При обрыве между записью и приёмом сообщения такой способ может пропустить уведомление.

После изменения частоты опроса один активный клиент за 60 секунд сделал 12 запросов вместо 43. Накопленное CPU-время контейнера веба снизилось с 2,52 до 0,86 секунды, PostgreSQL с 0,69 до 0,24 секунды. Замер выполнен на Docker Desktop. Для атрибуции пиков общего CPU на VPS нужны показания по контейнерам или процессам в момент пика.

После обнаружения повторяющихся пиков на VPS удалены периодические Docker-проверки веба и PostgreSQL. Подключение к базе проверяется один раз при запуске Compose. В Docker Desktop на свежем томе проверены успешное завершение этой проверки, ответ через Caddy и отсутствие команд Docker healthcheck у обоих контейнеров. CPU OCR-воркера ограничен 0,4 ядра. Замера VPS после этого изменения ещё нет.
